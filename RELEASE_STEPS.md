# Author-controlled publication steps

1. Review the exact candidate file manifest, version 2.0.0-rc1, known limitations, public visibility, ownership and proposed software license. Confirm the specific external action and actual GitHub/Zenodo destination accounts. No account has been selected or used in this task.
2. Adopt the approved license and update CITATION.cff with actual release date/version. Inspect the final archive locally and run the documented checks. Create a clean repository containing only approved release files, excluding output/cache directories. Check anonymous access to the code for editors/reviewers.
3. Follow the official Zenodo GitHub integration instructions to connect the correct repository and archive a tagged GitHub release; alternatively upload that exact approved archive to Zenodo. Check the deposited file manifest, metadata, version and accessibility. A reserved identifier is not evidence of a completed published archive.
4. Record the actual repository URL and version-specific permanent DOI/identifier and test them without account authentication. Update manuscript, cover letter and code statement only after this is real. Keep the concept DOI distinct from the cited version DOI. Obtain both authors' approval of the final manuscript after these edits.

Official instructions checked 2026-10-17: https://docs.github.com/en/repositories/archiving-a-github-repository/referencing-and-citing-content and https://help.zenodo.org/docs/github/ . Nothing has been uploaded or published by this task.
